# wrangl

wrangl is a controller that queues coding-agent **runs** onto **runners** (EC2 boxes, plus the
controller host itself as a permanent runner) and tracks work as a hierarchical **task** tree
inside **projects**. Use the `wrangl` CLI; on the controller host it talks to the running
controller over `~/.config/wrangl/config.yaml` (a unix socket), so no auth is needed there.
Elsewhere set `--controller https://ctrl.example.com` (Cloudflare Access applies) or
`WRANGL_CONTROLLER`.

Every command takes `-o json|yaml|table`; use `-o json` when you need to parse output.
Tasks are addressed by **sqid** (short id shown in `task tree`/`list`). Run `wrangl <cmd> --help`
for exact flags; this skill is the map.

## Tasks (the work stack)
- `wrangl task tree [--project P]` - ranked tree; `task list --project P --state S --parent SQID`.
- `wrangl task show SQID` - precursors, runs, history.
- `wrangl task create PROJECT --title T [--prompt TEXT | -f prompt.md] [--parent SQID] [--type TYPE] [--target-date YYYY-MM-DD] [--needs SQID...] [--repo owner/name] [--template NAME] [--after|--before SQID | --first | --last] [--issue owner/name#N]`
  The prompt is what the agent is told to do: make it self-contained (goal, constraints, done criteria).
- `wrangl task edit SQID [--title] [--prompt|-f] [--type] [--target-date YYYY-MM-DD]` (an empty `--target-date` clears it).
- `wrangl task move SQID [--parent SQID | --root] [--after|--before SQID | --first | --last]` - reparent or rerank.
- `wrangl task split SQID --title A --title B [--chain] [--copy-prompt]` or `-f outline.md` (one subtask per line, indent to nest); `--agent [--guidance TEXT]` queues a plan run that proposes the split for you to accept.
- `wrangl task needs add|rm SQID PRECURSOR` - ordering dependencies between tasks.
- `wrangl task ask SQID "question" [--agent NAME] [--wait]` - ask a controller agent (a light Claude on the controller host, with this skill) about a task and its subtree; answers collect in a thread on the task (`wrangl task thread SQID`, or the "Ask?" button); the agent may attach up to 5 proposed actions, approve one with `wrangl task apply MSGID N` (N is 0-based, as listed by `task thread`). Agents are registered in Settings > Controller agents.
- `wrangl task queue SQID [--agent NAME]` - queue a work run for that subtree (nothing runs until queued, unless the project has auto-queue). Works on any live task at any depth; if nothing is runnable it refuses and says why (e.g. "N subtask(s) are in review"). Overlapping subtrees are refused.
- `wrangl task dequeue SQID` - take that task's queued run back out of the queue (it stays open, in the backlog). Refused when nothing is queued (already running or never queued); a running run is stopped with `wrangl run cancel`. The project page offers the same as Queue / Dequeue / up-down / Stop / Queue all buttons.
- `wrangl task complete SQID [-m MSG]` (leaves only; parents complete when their subtasks do), `task reopen`, `task cancel` (with unfinished subtasks), `task delete` (whole subtree - confirm with the user first).

## Task types
`code` (default), `bug` (reproduce, failing test first), `ux` (mockups + prototype link; the owner reviews visually), `architecture` (an ADR; the owner reads before merge), `docs`, `research` (a report with sources; non-code knowledge work), `review` (findings, no diff), and the planning containers `release` > `milestone` > `feature` (a target date, a progress rollup, drawn bold; children of a planning task default to `code`). `spec` is an old alias of `docs`.
A release whose work is all done waits in review until the owner ships it (`wrangl task complete RELEASE`, or "Ship it" on the task page). Runs on a planning task work through its subtree; they do not do the container itself.
Agents hand back non-PR results with the `submit_deliverable` tool (image, prototype link, link, markdown report); the owner sees them on the task page and approves or requests changes from the inbox.

## Projects and repos
- `wrangl project list|show|create|edit|delete`; `project create SLUG --name N --template T [--auto-queue] [--auto-merge] [--priority N] [--description ...]`. Goals / definition-of-done markdown is edited on the web project page (`/project/SLUG`).
- Archiving: `wrangl project archive SLUG` hides a project and all its tasks and makes it inert; `wrangl project restore SLUG` brings it back; `wrangl project list [--archived | --all]` (default: active only; the two flags are mutually exclusive; the STATUS column says which). Archive is **refused while the project has active runs** (assigned, preparing, running, needs input, pushing or cancelling) and prints each one (run id, state, task sqid, title): wait for them or `wrangl run cancel` them, then retry. Queued runs are not blocking: archiving cancels them with the reason `project archived`, and they stay cancelled after a restore (queue the tasks again). While archived the project and its tasks are hidden from task lists, the Inbox, PR and run lists, log search, the agent tools' project list and the Settings/Tasks project pickers; the scheduler assigns nothing and launches no runners for it, tasks cannot be created in it (409 "project ... is archived"), PRs are neither reviewed nor auto-merged nor adopted, and `fleet.launch` for it is refused. `project show SLUG`, `task show SQID` and the project/task URLs still work. Nothing is deleted, and PRs are picked up again after a restore.
- Project settings: `wrangl project edit SLUG [--name] [--description] [--template T] [--priority N] [--auto-queue] [--auto-merge] [--auto-resolve] [--agent NAME] [--limit TEMPLATE=N]... [--citation-audit] [--notes-repo owner/name] [--plan-template T]` (only the flags you pass change).
  - `--limit TEMPLATE=N` (repeatable): per project x template limit on runner instances that project's demand may launch; default 1 for the project's default template, 0 for others (opt-in, e.g. Mac/Android). Effective cap = min(project cap, template `max_runners` account ceiling). In the project details panel (Runner limits); `wrangl project edit SLUG --limit TEMPLATE=N` (repeatable), shown by `project show`. Runners stay a shared pool; the cap governs launches.
  - `--citation-audit`: `wrangl project edit SLUG --citation-audit` (project `citation_audit`). For research-type PRs a read-only review run re-fetches every URL the PR adds and reports each as verified / unsupported / unreachable (`submit_citation_audit`); auto-merge needs all verified, otherwise the PR question shows a "Citation audit" section listing what to check. One audit per head commit.
  - `--notes-repo owner/name`: a linked repo that holds research reports under `research/` (empty clears). `--plan-template T`: the runner template for plan runs (default: the project template).
  - `--agent NAME`: the project's default agent definition (empty clears); see Agents below.
- `wrangl repo link PROJECT owner/name [--branch B]` (the account's GitHub App must be installed on the repo; add the account and create the App on the Setup page), `repo list`, `repo unlink`.
- `wrangl issue sync|list|show|to-task|drift` - pull GitHub issues in and turn them into tasks. `issue drift PROJECT [--repair]` lists issues whose synced copy differs from GitHub; `--repair` re-syncs them and drops rows GitHub no longer has.

## Runs, logs, questions, PRs
- `wrangl run list|show ID`, `run attach ID` (read-only terminal, replays from start), `run diff|files|cat ID`, `run cancel ID`.
- `wrangl logs RUN [-f] [--grep RE] [--since 15m] [--stream agent|runner]`; `wrangl logs search QUERY` (FTS5, all runs).
- Agents ask questions and request approvals: `wrangl question list`, `question show ID`, `question answer ID [--option X] [--text ...]`. Check these first when a run seems stuck.
- `wrangl pr list|show`, `pr approve` (approves and merges; a reviewer App is only needed if the repo requires approving reviews), `pr request-changes` (queues a revise run), `pr close` (tasks reopen).
- Merge conflicts: each open PR carries a stored mergeable state (unknown / clean / conflicted / blocked), refreshed on evaluate, `pull_request` and `push` webhooks and the reconcile poll; conflicted PRs get a "conflicts" pill and a Smart Merge action in the Inbox. `wrangl pr resolve <id>` (or `/ui/act/pr-resolve`) queues a `resolve` run that merges the base branch into the PR branch (merge, never rebase or force-push), resolves each conflict from both sides' intent, runs `./check.sh`/the test command, commits and pushes, asking the owner via the question tool when a product decision is needed. If the PR is not conflicted it calls GitHub's update-branch instead (no agent). One resolve run per PR at a time; the PR is re-evaluated at the new head and the outcome is logged as a `pr` entry. Auto-merge never merges a conflicted PR: with `wrangl project edit SLUG --auto-resolve` (default off) it queues Smart Merge, otherwise the PR question notes the conflicts.
- One PR per run: a run opens a single PR for its whole subtree, with a checkpoint commit per task; each task links to that PR (and its GitHub diff) from the task page. Expand an In progress task for its live output: the agent's own transcript rendered as Markdown (prose, one-line tool chips like `Bash: go test ./...` that open to a short, secret-redacted output excerpt, thinking collapsed), followed live until you scroll up, with a "load earlier" link. Finished runs show the stored entries without a live connection. If the run has no transcript (agents that don't write a Claude Code session file, or old runs) the card falls back to the read-only terminal with a note. `wrangl run attach` and the shell/agent terminals are unchanged (still the raw PTY). Transcript API: `GET /api/v1/runs/ID/transcript` (JSON tail with `limit`/`before`, or `?format=sse` with `Last-Event-ID` resume).

## Runners and templates
- `wrangl fleet list|show NAME`, `fleet launch --template T [--count N]` (new EC2), `fleet drain|cordon|uncordon|terminate NAME`. `wrangl fleet teardown [--region R] [--profile P] [--all-controllers] [-y]` terminates every `wrangl:managed` EC2 instance straight through AWS (works without the controller; asks first).
  Launched runners are reaped after the template's idle timeout (30m default); the controller host runner (`host-*`, template `host`) is permanent and cannot be terminated.
- Sessions per runner: template `max_sessions` (default 4); concurrent agent sessions each in their own git worktree; a runner is idle only at zero sessions; Runners page shows slots used/total.
- `wrangl template create -f file.yaml | edit | ...` - mise tools, setup script, agent command. Examples in `docs/wrangl/templates/`.
  Runner names are opaque labels (moving from `<template>-<hex>` to three-part music names like `cherry-rain-slowdive`); the template is a separate field (`fleet show`, `-o json`). Never parse a runner name for its template.
- `wrangl fleet enroll-token --template T` then `wrangl runner bootstrap --controller URL --token ...` adopts an existing machine; add `--host` to enrol the controller host itself under the current user (systemd --user unit).
- Web terminal: Runners view -> Terminal (`/runner/NAME/term`): a tab per agent session plus "+ Shell" (fish if installed, else bash). Shell tabs open in control; run tabs are watch-only until "Take control". The first shell on a runner installs bat, lsd, dust, duf, fd, ripgrep and tldr.
- Remote runners (experimental): template `mode: remote` + `connection: {driver_template, protocol ssh|adb, user, via ssm|direct, secret}`; the agent runs on a driver session and uses `target_exec` / `target_put`; the target runs no wrangl binary. `wrangl target list|terminate`. Runs take a target session and a driver session together; project cap defaults to 0 (`project edit --limit mac=1`). Lost target = run fails as target lost. See docs/wrangl/adr/0002-remote-runners.md and templates/remote-*.yaml.
- The controller agent (Ask? threads) can propose `fleet.launch {template, count}` (one click, 1-5 runners) for special-purpose runners such as Mac or Android; it is refused, naming the cap, unless the thread's project limit for that template (`project edit --limit`) allows it.

## Agents and credentials
- Agent definitions: named agents (claude, codex, gemini, antigravity...) separate from templates. `wrangl agent list|show|create -f SPEC|edit -f SPEC|delete|allow NAME --template T|disallow ...`; a template lists allowed agents (also `agents: [..]` in its YAML); `wrangl project edit SLUG --agent NAME` sets the project default; `wrangl task queue SQID --agent NAME` overrides per run. Choice: override, else project default if the template allows it, else the template's only agent. A run on a template that disallows the agent is refused at queue time with the allowed list. Existing templates were migrated (go-claude's agent is `claude`).
- Credentials: `wrangl secret set NAME` (stdin) / `secret list` over the API; `claude setup-token | wrangl agent auth claude` stores the Claude token; Settings -> Setup -> Agent credentials shows set/missing per agent secret (an agent spec's `auth:` section names the secret and the command that collects it).
- `wrangl secret set NAME` reads the value from stdin; `wrangl secret list` shows names only, never values.

## Web app (PWA)
Nav: Projects / Runners / Logs / Inbox / Settings; the five most recently updated projects are listed under Projects (on a phone, a project pill at the top of a project page opens a menu of projects plus "All projects"). **Projects** (`/projects`) is a table of projects with Runners, In progress, Queued, Backlog and Inbox counts; a row expands to show about, runners now (a runner that also serves another project is tagged "also serving X"), recent activity and Open / Comment / Edit / Archive; "New project" opens an inline form and archived projects are collapsed below with Restore. The **project page** (`/projects/<slug>`) shows the name and description, a strip (linked repos, "runners N active" popover listing every runner with a session for the project, concurrency per template, auto-merge, "Edit goals & repos" -> `/projects/<slug>/settings`, Archive), a "Needs you" strip with the project's open Inbox items (hidden when empty), a **Comment** button (project chat, see below) and three sections: *In progress* (runs assigned/running, with runner and the leaf being worked), *Queue* (queued runs: your order from up/down/drag, else tree position then FIFO) and *Backlog* (everything else, with "show done" under it). A queued or running task's whole subtree appears once in its section and not in Backlog. Row buttons: **Queue** on open top-level backlog rows (any live task can still be queued from its task page or `wrangl task queue`), **Dequeue** / up / down on queued rows, **Stop** on running rows, **Queue all** on the Backlog header; Stop, Queue all, Archive and every other destructive action ask inline ("Are you sure? Yes / Cancel"), never with a browser dialog. The acted-on row flashes. Old URLs redirect (302): `/tasks[?project=<slug>]` and `/backlog` -> `/projects[/<slug>]`, `/project/<slug>` -> `/projects/<slug>/settings`, `/` -> `/projects`. **Project chat** (Comment; right-hand panel on desktop, full screen plus a floating button on a phone; `/projects/<slug>?chat=1` opens it): a controller agent reads the project's tasks, runs, PRs and repos (context chip shows the counts), proposes changes as "Approve: ..." buttons (create/edit/move/split/queue/dequeue/reorder ... from a closed list, applied only on approval and refused if the project changed since), and `/queue <id|title>` / `/dequeue <id|title>` act at once without the model (an ambiguous title offers buttons); task ids in replies link to their rows. API: `POST /api/v1/projects/<slug>/ask`, `GET /api/v1/projects/<slug>/thread`, `POST /api/v1/project-thread/<id>/apply/<n>`, `GET /api/v1/projects/<slug>/runners`. Settings (text size, push, Setup: GitHub accounts, one App each, Projects, templates). Same data as the CLI; use whichever fits.

Web UI convention (for anyone changing the templates): state lives in Datastar signals or `data-preserve-attr`, not in JS, so live patches of `#main` cannot clobber it; sheets use `command="show-modal"`/`close`, menus use `popover`. See the README's "Web UI convention".

## Working rules
- Read first (`task tree`, `task show`) before editing or moving; confirm with the user before `delete`, `cancel`, `pr approve`, `fleet terminate`.
- Prefer `-o json` and quote prompts via `-f file.md` for anything multi-line.
- Don't queue broad subtrees without saying what will run and where. To start work, queue the smallest sensible subtree, after checking `wrangl run list` / Tasks (In progress, Queue) so you don't double-queue an overlapping one.
- Verify flags with `wrangl <cmd> --help` before relying on them.
