# wrangl v0.1.0

The first release of wrangl, a self-hosted controller that runs a ranked backlog of tasks on a fleet
of coding agents (Claude Code, Codex, Gemini CLI, Antigravity) and brings the questions and pull
requests back to you, from a phone if you like. It is one Go binary: controller, runner, CLI, TUI and
MCP server. This release adds prebuilt binaries and a one-line installer.

## Highlights

- **Install in one line.** `curl -fsSL https://github.com/AgenticWrestling/wrangl/releases/latest/download/install.sh | sh`
  puts a checksum-verified `wrangl` in `~/.local/bin`. Prebuilt for macOS on Apple silicon and Linux on
  x86_64 and arm64; on Windows use WSL or build from source.
- **A ranked backlog that runs itself.** Projects, then release > milestone > feature > task, with
  dependencies, typed tasks and GitHub issues pulled in as tasks. Queue any task at any depth: wrangl launches
  an EC2 runner from a template, runs the agent in a PTY with a checkpoint commit per subtask, opens a pull
  request, runs a separate review, and auto-merges low-risk work. Runners are reaped after 30 idle minutes.
- **One Inbox, mobile first.** Questions, approvals, plan proposals, task and PR reviews, deliverables and
  tool failures arrive in one place in an installable PWA with web push.
- **Drivable by agents.** An owner MCP endpoint (`/mcp`) exposes the work stack, projects, the Inbox, runs,
  logs, pull requests, repos, issues, runners, templates and agents as tools; see
  [docs/wrangl/mcp.md](../wrangl/mcp.md).

## Changes

- Projects as the primary lens: per-project queue, backlog, runners, "Needs you" strip and a project chat
  agent that proposes changes you approve with a button.
- Multi-session runners (several agents per runner, each in its own git worktree off a shared mirror),
  per-project instance limits per template, named agent definitions separate from runner templates.
- One GitHub App per account created through GitHub's manifest flow, optional reviewer App, Smart Merge for
  conflicted PRs, research citation audit before auto-merge.
- Agent GitHub issue tools (search, read, comment, create, edit; closing needs your approval).
- Remote runners: an agent can drive a Mac or an Android emulator host over SSH or ADB (experimental).
- Inbox: failed tool calls surface immediately as a notice, change links open the GitHub commit or PR, stopped
  agents ask a proper "What now?" question.
- Documentation: a README with a getting-started path, [DESIGN](../wrangl/DESIGN.md),
  [DEVELOPMENT](../wrangl/DEVELOPMENT.md), deep-dive guides on projects, tasks, runners and scheduling, and
  ADRs 0001 to 0009.
- Release tooling: `task prerelease` and `task release`, and a `wrangl version` command.

## Upgrading

This is the first tagged release; there is nothing to migrate from. For an existing controller, an upgrade
replaces the controller binary and the two runner binaries (`wrangl-linux-aarch64`, `wrangl-linux-x86_64`);
runners upgrade themselves when idle, and database migrations run on controller start. See INSTALL.md,
"Upgrades".

## Known issues

- Tested against fakes for AWS, GitHub and the agents; a real first run still needs the checklist in
  [INSTALL.md](../wrangl/INSTALL.md). Only the Linux runner image is built and tested; macOS and Android
  runner images are planned.
- An owner's late answer to an agent question that has already timed out is lost, one blocker can show as
  three Inbox cards, and tasks completed by a still-running run show no review card until that run ends.
- Scheduling limits: one template per run with no fallback, and the host runner is invisible to projects on
  other templates. The proposed fixes (ADR 0007 and 0009), custom per-project tools (ADR 0003) and the action
  state machine (ADR 0006) are designed but not built.
- No prebuilt binary for Intel Macs or native Windows.
